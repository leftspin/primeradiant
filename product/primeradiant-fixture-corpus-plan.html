Fixture corpus

Golden corpus plan

A small, inspectable dataset that proves primeradiant is doing story-state maintenance instead of summarization cosplay.

1. Corpus doctrine

The corpus is a product test, not demo data. It must make wrong architecture fail: generic summaries, destructive merges, fake novelty, missing seen-state, and ungrounded narration should all be caught.

Small enough to read

Every input, expected edge, and expected briefing should be manually inspectable.

Rich enough to break cheats

The same story must include duplicate, update, contradiction/framing, user priority, and stale/no-op paths.

Stable enough for tests

The corpus becomes the first regression suite for agents, projections, authoring, and seen-state.

4. Required story mechanics

Material update

Something actually changed

An input must force story state to update and justify telling the user.

Duplicate/reinforcement

More source weight, not fake novelty

An input repeats the substance of an earlier one. It may affect confidence/social weight, but not “what changed.”

Correction/contradiction

The graph changes its mind safely

A later input conflicts with a prior claim and should create contradiction/supersession state, not silent rewrite.

Personal watch

User priority beats global rank

A watch from /preferences/priorities or /stories/concepts attaches to relevant story state even when graph gravity is low.

Staleness/no-op

Nothing happened is still state

A related input that does not materially change the story should be classified as no-op/related, and a dormant story should become stale without disappearing.

Seen-state delta

New to this user

The second briefing must exclude what was already shown and include only material changes since the first authored output.

5. Expected edge set

The fixture should require at least these named relationships:

  • supports — input supports claim/story.
  • updates — input materially changes story state.
  • duplicates — input repeats prior substance.
  • contradicts — input conflicts with claim/story state.
  • adds_color — input adds context but no material update.
  • part_of — private/public substories can attach to larger story if warranted.
  • watch_applies_to — user watch attaches to story/concept/claim.

6. Starter acceptance tests

  1. After first pass, corpus produces at least one Story node, multiple Input nodes, Claim/Entity nodes, and named edges.
  2. No committed edge has type related.
  3. Duplicate input does not appear in story.delta as a material update.
  4. Correction input creates contradiction/supersession state with provenance.
  5. User watch attaches through watch_applies_to and can raise user relevance independent of global gravity.
  6. First briefing records seen-state at story/input/claim/output level.
  7. Second briefing excludes already-seen facts and leads with the new material delta.
  8. Stale/no-op case changes freshness/activity state without deleting or rewriting story identity.
  9. Every authored material sentence traces to evidence refs.

7. Fixture authoring rule

Use synthetic but realistic content. Do not use demo shortcuts that bypass production invariants. Fixture inputs should pass through the same ingestion, proposal, arbitration, projection, authoring, and seen-state paths as real data.

No cheating: expected outputs are for tests; they must not seed trusted production state or bypass the soup.
