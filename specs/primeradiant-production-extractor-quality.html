T321 source-of-truth spec after T312 proof

Production extractor quality

Defines the next Primeradiant boundary: can production extraction turn messy real-world inputs into trustworthy story facts without fixture labels, story hints, or demo shortcuts?

2. Product Purpose

Purpose

Evidence into story facts

Read one admitted source item and emit structured, span-backed claims, entities, times, source stance, uncertainty, framing, and refusal state that downstream systems can validate and use.

Product question

Trust without labels

The extractor must work when the input has no fixture ID, expected label, story hint, preselected story, source file order, or hard-coded corpus vocabulary.

Boundary

Extractor only

The extractor does not fetch sources, rank stories, choose headliners, author user copy, run a production daemon, or commit graph truth.

2.1 Non-Goals

  • No connector implementation: no RSS, email, message, social, web-search, browser, or document acquisition connector.
  • No daemon/runtime shell, background service, Oban production lane, swarm scaling, deployment, release packaging, merge, or production config.
  • No UI, story dashboard, proposal review screen, ranking/headliner system, feed placement, notification threshold, or authored briefing output.
  • No story identity invention beyond extractor output. Story attachment, split, contradiction, personal relevance, and seen-state decisions remain downstream responsibilities.
  • No broad world-truth validation. The extractor records what the source says, how strongly it says it, and what evidence span supports it; it does not decide whether the world is actually that way.
  • No schema expansion unless the implementation proves the existing normalized envelope cannot represent a required extractor field. A missing convenience column is not a blocker by itself.

3. Input Classes and Messy Failure Modes

T321 extraction starts after real admission. Inputs are admitted source items or normalized input rows from manual_real_ingest_v1. They may be public or private, but they must already carry tenant, ACL, source identity, timestamps, text or artifact reference, and provenance.

Input classExamplesExtractor obligation
Reported public articleNews article, agency wire, institutional update, filing excerpt.Extract asserted claims, named entities, event/time scopes, attribution, and correction language without assuming the source is true.
Opinion or analysisColumn, editorial, blog analysis, pundit post.Separate factual assertions from interpretation. Preserve framing as source stance or color unless a span directly asserts a structural fact.
Private thread itemEmail, message, user note, project update.Extract task/decision/deadline/question facts with participant/source context while respecting ACL and private provenance.
Thin or partial pageSearch snippet, landing page, copied excerpt, clipped text.Emit low-confidence or refusal state when spans are insufficient. Do not manufacture missing facts to make story identity easier.
Correction or updateCorrection notice, revised article, later message, follow-up filing.Preserve prior/new timing and source stance so downstream contradiction logic can distinguish correction, update-over-time, and disputed fact.
Quoted or attributed sourceArticle quoting an agency, company, witness, or anonymous source.Represent who asserts the claim: publisher voice, quoted actor, unnamed source, reported allegation, or source characterization.
Compound itemArticle with multiple sub-events, thread digest, mixed public/private note.Emit multiple atomic claims and entities with spans. Do not collapse distinct situations into one topic label.

3.1 Failure Modes That Must Be Tested

  • Boilerplate contamination: navigation text, ads, unrelated recommendations, email footers, legal disclaimers, and share buttons must not become story facts.
  • Headline/body mismatch: a sensational or stale title must not override body evidence. Claims cite body spans unless the headline is the only available evidence and is marked as such.
  • Multi-story collision: one source may mention several events. The extractor emits separate claims/entities/events; it does not choose a single story container.
  • Near-miss identity anchors: same topic with different venue, actor, date, scope, or affected group must preserve those anchors so downstream identity can split correctly.
  • Quote laundering: a quoted accusation, rumor, denial, or campaign framing must not be promoted into publisher-asserted fact.
  • Opinion-as-fact drift: evaluative language, blame assignment, motives, and strategic spin stay source stance/framing unless directly evidenced as an observable fact.
  • Temporal ambiguity: vague times such as "today", "last week", "since Friday", and "by tomorrow" are normalized only relative to source timestamps and carry ambiguity when needed.
  • Correction ambiguity: later text may correct a prior report, describe a new state, or dispute a source. The extractor must preserve correction cues and time scope, not pre-decide contradiction.
  • Negation and modality: "did not approve", "may approve", "denied reports", and "plans to approve" must not be extracted as the same positive asserted fact.
  • Thin evidence pressure: if the item lacks enough text to support a fact, the correct output is low-confidence/refusal, not a generic topic claim.
  • Private source leakage: source actor, participants, and spans from private items remain in ACL-scoped output and cannot be copied into public story state by extraction.
  • Fixture-shaped cheating: expected labels, file names, fixture IDs, story hints, external IDs, and source order must not influence claim or entity extraction.

5. Preserving Spin Without Promoting It

Primeradiant needs source perspective because stories are contested and framed. The extractor must preserve that framing while preventing it from mutating structural story facts by accident.

Source text patternExtractor treatmentDownstream effect
"Officials blamed early reports for confusion."Framing item: blame. Claim only if the source directly says officials made that statement.Can feed adds_color or source-stance context; does not overwrite the factual cause of confusion.
"The shutdown was avoidable."Opinion/framing unless the source provides a specific attributed decision/fact.Preserved as color; not a structural fact that the shutdown was avoidable.
"The agency denied that service was halted."Claim with modality denied, attribution to agency, target fact service_state=halted if span supports it.Can become a contradiction candidate only with attribution/modality visible.
"A source said talks may resume Friday."Claim with modality possible or reported, anonymous attribution, Friday time scope with uncertainty.Can inform unresolved/follow-up state; does not become a confirmed schedule.
"Commuters stood in the rain waiting for buses."Human-color framing plus observable claim if directly stated.Can enrich narration if cited; only the observable part may become a structural/background claim.

5.1 Hard Rules

  • Framing items set promoted_to_structural_fact: false. Promotion requires a separate claim with its own evidence span and non-opinion modality.
  • Perspective does not create updates, contradicts, or material deltas by itself. It feeds adds_color unless paired with a structural claim.
  • Source stance is evidence context, not story identity. Opinion articles can contain factual claims; news articles can contain spin. The span and modality decide treatment.
  • Downstream authoring may say "the columnist frames this as..." only from framing evidence. It must not say "the story is..." unless structural claims support it.

6. Downstream Handoff

The production extractor feeds the already-proven story-semantics path by providing higher-quality, evidence-backed atoms. It does not replace the downstream deciders.

Downstream judgmentExtractor fields usedRequired boundary
Story identityStructural claim candidates, entity canonical keys, event/time scopes, source-thread hints, evidence refs, uncertainty.Extractor emits anchors. Candidate retrieval and identity decider choose attach/split/part_of/abstain.
Novelty and no-opFact keys/values, claim modality, time scope, evidence hash, source stance, duplicate text hash.Extractor does not mark material delta. Projection and story events decide whether a fact is new to story state.
ContradictionComparable fact keys/values, polarity, modality, attribution, time scope, uncertainty, correction/denial stance.Extractor identifies comparable claims. Conflict logic decides true contradiction versus update-over-time, denial, opinion, or scope difference.
Personal relevanceEntities, projects, deadlines, tasks, participants, private source actor, watchable anchors.User watch matcher and relevance projections decide personal importance. Extractor does not boost or rank.
Seen-state deltasStable claim IDs, evidence refs, material claim candidates, framing items, questions.Authoring and seen-state writers decide what was shown. Extractor does not mark anything seen.
Grounded authoringEvidence spans, stance, uncertainty, framing, attribution, open questions.Authoring may use only visible evidence packets and must preserve uncertainty. Extractor output is not prose-ready truth.

6.1 Mapping to Existing Real-Ingestion Envelope

  • claims map to extracted.claims with richer modality, attribution, uncertainty, and time scope.
  • entities map to extracted.entities, replacing title-case convenience extraction with role-aware entities.
  • source_stance replaces the single posture field when multiple attributions appear in one item.
  • framing maps to colors for the current storage vocabulary and later can become perspective nodes if separately specified.
  • quality.status = low_confidence/refused maps to downstream abstain or needs_more_evidence. It must not synthesize topic-only facts.

7. Eval Corpus Shape

The eval corpus is an extractor-quality corpus, not a story-label corpus. It may contain expected outputs for assertions, but production extractor code cannot read expected labels, story IDs, or fixture metadata.

7.1 Corpus Packs

PackMinimum shapeMust prove

Opinion and framing6-10 opinion/analysis items that mix factual claims, blame, reassurance, criticism, rumor, and human color.Framing preserved as framing; factual claims extracted only when span-supported and modality-correct.

7.2 Fixture Discipline

  • Inputs may have stable test IDs for file management, but extractor code cannot read IDs, paths, filenames, expected artifacts, story labels, or answer keys.
  • Expected outputs live only under eval assertion files and are loaded after extraction. They are never available to the extractor, prompt, candidate retrieval, proposal builder, or downstream decision code.
  • Each eval item includes source text, source metadata, ACL, retrieval/observed timestamps, and optional raw artifact text. It does not include trusted story identity.
  • At least 25 percent of corpus items must be negative or partial cases where the right behavior is low-confidence, refusal, framing-only, no-op, or no structural claim.
  • The corpus must include adversarial examples where a title, source URL, or external ID suggests the wrong answer.

8. Acceptance Gates

T321 passes only when extractor output quality is sufficient to feed the proven story-semantics path without labels or demo shortcuts.

8.1 Contract Gates

  1. Every extractor result validates against production_extractor_v1.
  2. Every non-refused claim, entity, time, stance, framing item, and question has evidence refs with valid spans and input ACL.
  3. Every structural claim has fact key/value or an explicit reason it is not comparable yet.
  4. Every claim has polarity, modality, attribution, time scope, uncertainty, and downstream use.
  5. Low-confidence/refusal outputs contain no structural claims and produce downstream abstain or needs_more_evidence.
  6. Private evidence refs are unavailable to unauthorized actors in retrieval, proposals, authoring, and eval inspection.

8.2 Quality Gates

  1. Claim extraction precision on gold structural facts is at least 0.85; recall is at least 0.75 on answerable claims. Refusals and explicitly unanswerable items are excluded from recall denominator but counted in refusal accuracy.
  2. Entity extraction precision is at least 0.85 for story-relevant entities and at least 0.80 for role assignment.
  3. Time-scope normalization accuracy is at least 0.80 on answerable temporal claims, with relative-date basis recorded.
  4. Source stance/modality classification accuracy is at least 0.85 for opinion, correction, denial, quote/allegation, and reporting cases.
  5. Framing preservation accuracy is at least 0.85: spin/framing is captured when present and not promoted to structural fact.
  6. Low-confidence/refusal accuracy is at least 0.90 on thin, malformed, boilerplate-only, and unsupported cases.
  7. False structural fact rate from boilerplate, headlines unsupported by body, quoted rumors, and opinion framing is below 0.05.

8.3 Downstream Integration Gates

  1. Extractor output drives all existing decision categories at least once: attach, split, part_of, conflict, no_op, color, stale, and abstain/needs_more_evidence.
  2. Near-miss items split when identity anchors differ by venue, actor, time scope, or affected group.
  3. Meaningful repeats attach when they add a new question, actor, deadline, amount, or other material claim; exact repeats stay no-op.
  4. Contradiction checks use extracted fact key/value, polarity, modality, attribution, and compatible time scope, not correction keywords alone.
  5. Opinion/framing items produce adds_color behavior and do not advance last_material_at unless a separate structural claim is extracted.
  6. A low-global-rank private/user-watch item can still become personally relevant through watch matching, but extractor output itself does not rank it.
  7. After a verified authored output, a second delta includes only unseen material claims and watched updates; it excludes no-op repeats and spin-only items.
  8. Proof harness, storage harness, and Postgres schema validation remain green after integrating extractor output.

8.4 Forbidden Pass Conditions

  • Any extractor behavior branches on fixture ID, filename, external ID pattern, story hint, expected role, expected story, expected classification, or eval answer key.
  • A regex or prompt is tailored to the eval nouns instead of the contract: ferry, roof, civic clinic, basement, bridge, summit, or any future corpus-specific names.
  • A claim is accepted without evidence spans because it "looks right" from the title or source metadata.
  • A quote, allegation, denial, or opinion is stored as publisher-asserted structural fact without modality/attribution.
  • A thin item is forced into a structural claim to keep downstream story identity tests passing.
  • Downstream code compensates for extractor weakness by adding story-specific heuristics outside the extractor contract.

9. Exact Next Implementation Slice

The next slice after this spec is a production-extractor contract and eval path inside the current harness boundary. It is not a connector, daemon, UI, deployment, ranking, or merge task.

  1. Add a Primeradiant.Extraction boundary in the storage harness or next Phoenix context with extract(input, opts) :: {:ok, extraction_result} | {:error, changeset}.
  2. Define production_extractor_v1 JSON Schema or Ecto embedded schemas for extractor result, claim, entity, time, source stance, framing, evidence span, quality status, uncertainty, and refusal reasons.
  3. Store extractor output under the existing input normalization/provenance path with extractor_version, contract_version, trace metadata, and immutable source evidence hashes.
  4. Create the extractor eval corpus under the shared primeradiant harness area with the six packs in section 7. Expected outputs must be assertion-only and unavailable during extraction.
  5. Implement the first extractor behind the contract. It may combine deterministic parsing and model-assisted structured output, but it must validate every result and abstain/refuse instead of inventing unsupported structure.
  6. Replace downstream use of RealNormalizer convenience grammar in the integration eval with the production extractor result adapter. Keep old fixture/proof paths isolated as regression harnesses only.
  7. Add eval tests for contract gates, quality gates, forbidden pass conditions, and downstream integration gates. Include tests that fail if code reads fixture labels, story hints, filenames, or expected artifacts.
  8. Run storage harness tests, proof harness tests, extractor eval tests, and live Postgres schema validation before reporting readiness for Flynn verification.

10. Implementation Handoff Boundaries

  • Implement exactly the extractor contract and eval path above. Do not add connectors, acquisition loops, UI, ranking/headliner behavior, daemon/runtime shell, deploy scripts, or merge workflow.
  • Do not infer product truth from current code convenience. Existing regex grammar is evidence of a tested boundary, not evidence of broad extraction quality.
  • If a required field cannot be represented in the current normalized payload, stop and amend this spec or the storage spec. Do not hide the field in ambiguous maps without a named contract.
  • If model output is used, every model response is hostile until schema validation, span validation, evidence visibility checks, and confidence/uncertainty checks pass.
  • If eval quality misses a gate, report the miss. Do not tune the corpus, remove hard items, or add item-specific shortcuts to pass.
