Janus ticket T1618 · branch primeradiant-spirit-ecology-recon · recon date 2026-07-09 · produced on eezo by the T1618 Claude/Fable recon session. Every requirement, finding, and recommendation carries a stable ID (S/B/D/T/C/G/R/N) for citation in follow-up review.

1. Spirit

S1. Prime Radiant is an ecology of agents making sense of a soup of items dumped into it from many sources.

Decomposition of S1 into testable clauses (all later gaps cite these):

S2 — "an ecology of agents"
Multiple coexisting agent species, autonomous within bounds, coordinating indirectly through the shared substrate — with ecological dynamics: activity, budgets, decay, quarantine/composting, homeostasis. Not a single batch pipeline.
S3 — "making sense"
Sense-making (story identity, meaning, linking, contradiction, revision) is the product. Conclusions are provisional, revisable, evidence-backed, and provenance-stamped.
S4 — "a soup of items"
A permissive, heterogeneous, shared substrate. Items are admitted as evidence; structure is earned downstream, never required at the door.
S5 — "dumped into it"
Admission is cheap, push-shaped, and unconditional on meaning. The soup does not gatekeep on understanding; sources do not decide story meaning.
S6 — "from many sources"
Source plurality is first-class: per-source identity, provenance, and health. One stalled source must be visible and must not mask the others.

2. Brainstorm — what the spirit implies (written before reading code)

These were derived from S1 alone, per the ticket instruction not to infer product truth from the current implementation.

B1 · Product shape
The soup is a permissive intake pool: admission must be cheap and schema-light, never blocking on downstream understanding.
B2 · Product shape
"Many sources" demands per-source identity, per-source health, per-source provenance as first-class axes.
B3 · Product shape
Sense-making output is emergent, revisable structure (stories, claims, relationships, evidence) — never one-shot ETL output.
B4 · Product shape
Ecology implies lifecycle: birth (admission), growth (linking/enrichment), decay (staleness), composting (cleanup/quarantine), homeostasis (health). Deletion is rare; state transitions are the norm.
B5 · Architecture
Blackboard/stigmergic architecture: agents coordinate through what they read/write on the soup, not an orchestrator call-graph. Adding an agent species should require no changes to other agents.
B6 · Architecture
Every agent output is a provenance-stamped annotation; raw items are never destroyed by interpretation (effectively event-sourced).
B7 · Architecture
Substrate/product boundary: PR exposes neutral truth, material, health, query capability; consumers own projections, thresholds, readiness, fallback. PR must not branch on consumer needs.
B8 · Code ownership
Each agent species is an independently owned, independently testable unit with a stable soup contract (read query + write schema). Shared code is substrate plumbing, not agent logic.
B9 · Code ownership
Prompts are code: versioned, evaluated against fixtures, tied to agent-run provenance.
B10 · Runtime topology
An ecology is resident and continuous: long-lived supervised processes reacting to soup deltas, with timers only as heartbeat/backstop. If everything only runs when a timer fires, it is a batch pipeline wearing an ecology costume.
B11 · Runtime topology
Population control: concurrency limits, per-agent budgets (LLM spend, rate limits), backpressure when inflow exceeds digestion capacity.
B12 · Data model
Core nouns: source, source-event, soup item, admission record, agent run, annotation/claim, story, relationship, evidence link, quarantine record — all linked by provenance.
B13 · Data model
Story identity is a sense-making conclusion (revisable), not an ingestion-time key.
B14 · Observability
Health per ecological function, with distinct signals for "upstream stopped delivering" vs "agents stopped digesting" vs "the timer stopped firing." These must never be conflated.
B15 · Observability
The substrate should be queryable about its own health, so operators and consumers ask the soup, not the logs.
B16 · Failure handling
Graceful degradation: one sick source/agent/story never halts the rest; failures produce retry/quarantine state on the item, not pipeline abort; reprocessing is idempotent.
B17 · Failure handling
Poison items are composted: quarantined with reason and provenance, inspectable, re-admittable after repair.
B18 · Agent behavior
Agents are delta-driven, bounded, idempotent, provenance-stamping, self-reporting, and contract-conformant (structured outputs validated at the boundary).
B19 · Agent behavior
Agents may disagree; the soup holds competing interpretations with evidence, and later adjudication resolves them. Disagreement is data, not error.

3. Source Docs Read

All 13 assigned docs were read in full, plus three additional live docs found beside them. Key spirit-relevant truth per doc:

D1 — whitepaper/primeradiant-architecture-whitepaper.html
Defines the three-layer vision: soup (semantically rich, possibly-cyclic graph with legitimate islands), swarm ("many narrower agents with different jobs," nine named roles), authoring system, plus an agentic "spelunking" API. Named edges only ("an edge should not merely say 'related'"), relationships carry provenance, merge/split is non-destructive, ranking is emergent, staleness and seen-state are first-class. Explicitly rejects "memory store," feed reader, and dedupe-engine framings.
D2 — architecture/primeradiant-system-architecture.html
Implementation-ready commitments: Elixir/Phoenix with "OTP is not an implementation detail… the natural runtime model for supervised swarm agents"; PostgreSQL 17 + pgvector as system of record; Oban queue lanes (ingestion, extraction, swarm, arbitration, projection, authoring, maintenance) as backpressure vocabulary; eleven named seams S1–S11 (only the Soup Core Write Seam commits; all agents propose); 16-agent catalog with prompt kernels; observability doctrine "Agents without traces are bugs."
D3 — architecture/primeradiant-agent-prompt-pack.html
Prompt contracts per agent with shared output envelope, abstention semantics ("Prefer abstention over weak invention"), risk-flag vocabulary, and a prompt-registry schema (versioned prompts with hashes and eval sets).
D4 — architecture/primeradiant-elixir-contracts.html
"Agent output is hostile until validated." Typed graph ops only; forbidden ops delete_story, merge_story_destructive, rewrite_seen_state, commit_without_evidence, generic_related_edge; seven ordered validation gates; context API signatures for Soup/Proposals/Arbitration/Authoring.
D5 — architecture/primeradiant-elixir-implementation-blueprint.html
Always-on supervision tree (Repo, PubSub, Oban, ModelClientSupervisor, AdapterSupervisor, MCP server); non-negotiable gates: no agent writes committed state directly, everything validates through JSON Schema + Ecto, staleness is state not timestamp, "the first code should be a story-semantics proof harness, not a product app."
D6 — architecture/primeradiant-phoenix-module-map.html
"Contexts own product truth"; workers orchestrate only; agents cannot call commit functions; the golden-corpus end-to-end test is the product guardrail ("if it passes only through shortcuts or seeded trusted state, the implementation is cheating").
D7 — architecture/t1178-live-gibson-ecology-correction.md
Flynn's ecology invariant: live configured agents must run model inference over soup contents and produce candidate mutations through mediated writes — recorded transcripts do not count. Establishes Primeradiant.Mediation.WriteGate as mechanical containment (schema/evidence/permission/visibility/atomicity), explicitly not truth arbitration; live route is Gibson/Qwen.
D8 — product/primeradiant-implementation-roadmap.html
Seven phases, each preserving the same proof: fragments → story state → user-relative deltas → evidence-backed proposals → grounded output. Real connectors deliberately last ("Real connectors create noise before the story-state loop is proven").
D9 — product/primeradiant-mvp-slice.html
Hybrid slice (public story + private thread + user watch + stale/no-op case) proving cross-source story identity, user-relative novelty, evidence-backed narration, staleness. All graph-changing agents propose, never commit.
D10 — product/primeradiant-fixture-corpus-plan.html
Golden corpus is "a product test, not demo data" — designed so generic summaries, destructive merges, fake novelty, missing seen-state, and ungrounded narration fail. Fixtures must flow through the same production paths as real data.
D11 — specs/primeradiant-real-ingestion-story-identity.html
Real admission seam: evidence-only, label-free (fixture_id and all expected_*/story_hint fields rejected), content hash is dedupe fingerprint not story identity; seven decision types (attach/split/part_of/conflict/no_op/color/stale) with named-edge proposal obligations; "topic overlap alone is never enough for attach."
D12 — specs/primeradiant-production-extractor-quality.html
T321 extractor contract: span-backed claims with polarity/modality/attribution/time-scope/uncertainty; refusal is a successful product behavior; numeric quality gates (claim precision ≥ 0.85, false-structural-fact rate < 0.05); framing feeds adds_color, never material deltas.
D13 — specs/primeradiant-storage-schema-hardening.html
"Postgres is the v1 system of record." 18 canonical tables; DB-level enforcement (graph-commit boundary trigger, edge_type <> 'related' check, verified-output-before-seen-state trigger); Arbitration.commit/2 is the only production path allowed to create graph commits.
D14 — specs/primeradiant-eurisko-soup-api-deploy-runbook.md

5. Current Code Shape

The repo holds the spec docs plus two Elixir apps. Findings (file:line evidence available in each):

C1 — No OTP application anywhere
Neither app declares a mod: in application/0 (proof-harness/mix.exs:14-18, storage-harness/mix.exs:15-19); zero GenServer/Supervisor/spawn/Task usage across both lib/ trees. There are no supervised processes, no PubSub, no Oban.
C2 — The production "agent ecology" is a sequential in-process chain
LiveStoryAgentLoop.run_for_admission (storage-harness/.../live_story_agent_loop.ex:335-467) runs story_identity → meaning_update → story_synthesis as plain function calls per admitted input inside one process. Agents never observe the soup independently, never run concurrently, and coordinate only via the hardcoded next-step call.
C3 — Trigger/lease/cascade-budget scheduling exists only as proof fiction
Primeradiant.Agentic.EcologyRuntime fabricates trigger rows, lease records, suppressions, and failure taxonomies as literal maps with frozen timestamps (@proof_now = "2026-06-04T20:00:00Z", ecology_runtime.ex:10-11, 206-281, 294-338, 677-735) and self-audits against its own construction. Nothing in storage-harness implements triggers or leases.
C4 — The only recurring runtime is a 15-minute systemd oneshot, and its default synthesis is not an agent
Cadence mode without a custom adapter replaces story synthesis with deterministic packet-completion or refusal — producer_kind: "deterministic_product_logic", route internal://story-synthesis/grounded-cadence-packet (live_story_agent_loop.ex:219-261). Live model inference happens only on event-driven ingest with --story-agents (off by default) or backfill.
C5 — The soup is load-mutate-rewrite of a SQLite file via the sqlite3 CLI
Whole tenant state loads into one struct, mutates in memory, and re-persists by shelling out (durable_soup_db.ex:30-101, 1242-1256). Concurrency safety is a single abort-on-revision-mismatch guard. The Ecto Postgres Repo (5 lines) and the hardened Postgres migration with its enforcement triggers are test artifacts unused at runtime.
C6 — Production writes are self-approved
The live loop inserts proposals pre-set status: "accepted", ops pre-set "committed", and authors its own decision row (actor_type: "agentic_write_gate", live_story_agent_loop.ex:1470-1650). The proof-harness Mediation.WriteGate validation (write_gate.ex:380-518) is not used by the production path; the Postgres commit-boundary trigger that would enforce it doesn't run on SQLite.
C7 — One model, hardcoded endpoint, shell-out transport
All live agents call one Qwen model at hardcoded http://gibson:8080 via System.cmd("curl", …) with raise-on-failure (live_gibson.ex:4-5, 30-48). No per-agent model routing despite registry rows claiming model_route; no retry/backoff at transport level; a transport failure crashes the task.
C8 — One real source family live
Production adapters: daemon-news event envelopes (single message type swarm.channel.news.report.v0) plus a one-off uveal-research importer. No persistent emitter/watcher is installed (daemon_news_event.ex:82-83); the r1 scripts are explicitly one-shot/manual. Argus appears only as a test-fixture string.
C9 — Substrate branches on a specific consumer
Primeradiant.Soup hardcodes consumer must be reporter and projections story_cards/news-morning (soup.ex:114-137) — the substrate names and rejects consumers/projections rather than treating them as dumb filter inputs.
C10 — Two parallel, divergent soup implementations
proof-harness has its own store/normalizer/classifier/write-gate over fixtures (with fixture-phrase keyword rules, normalizer.ex:54-148); storage-harness re-implements identity/meaning/synthesis differently (live path reduces the 13 specced op types to essentially record_event-shaped writes).
C11 — Observability is thin but health semantics are good
No Logger, no telemetry, no metrics; audit events live in memory; task output is one JSON blob via Mix.shell().info. Credits: /ready exposes freshness + synthesis-health blockers, and /delta has explicit cursor-gap/epoch semantics instead of silent loss (soup.ex:9-228).
C12 — Failure handling is partial
Story synthesis gets one schema-repair retry and one coverage-repair retry, then a typed refusal card with quarantine_recommendation (live_story_agent_loop.ex:596-830) — good composting. But transport errors raise, and there is no backoff, no dead-letter path, no per-item retry state.
C13 — Quarantine is real and well-built
T1421 plan/apply quarantines rather than deletes (full original-row JSON preserved, plan hash verified twice, operator approval required, live_data_cleanup_apply.ex:19-231), and Primeradiant.Soup excludes quarantined stories from served projections (soup.ex:585-616). This matches B17 exactly.
C14 — Contract discipline at admission is real
Ingestion.Admission rejects trusted labels (fixture_id, story_hint, expected_*), enforces ACL, dedupes by external-id and content hash (admission.ex:8, 117-129) — matching D11. The deterministic T321 extractor is span-backed and refusal-capable, though regex-based rather than model-based.

7. Recommendations

Each carries its change type. R1–R4 are the spirit-critical core; the rest compound them.

R1 — Repair upstream source delivery and make source health substrate-visible runtime topology changeobservability change
Execute the approved T1430 watcher-authorization repair, resolve the T1449 FK persist failure, and drive the Argus/Subspace daemon-row outage (capped 2026-07-07) as its own incident. Then add per-source freshness rows to substrate state (last event id/time per source, admission lag) served through the existing neutral health surface — so "upstream stopped" is a queryable soup fact, not a log archaeology exercise. An ecology with no food is not an ecology (G6, G7).
R2 — Make storage-harness a real OTP application architecture changeruntime topology change
Add an Application module and supervision tree: a soup-DB owner process (single writer; today's revision-guard becomes transactional), the Plug endpoint as a supervised child (replacing mix primeradiant.soup_api + Process.sleep(:infinity)), and an agent supervisor. Run the release under the existing systemd unit unchanged. This is the smallest step that turns "scripts sharing a SQLite file" into a resident system and unlocks R3/R5 (G1, G5-adjacent).
R3 — Implement the trigger/lease scheduler for real: resident, delta-driven agents architecture changecode change
Replace the EcologyRuntime proof fiction with production code: admission events and soup-change deltas enqueue bounded agent work; supervised workers take leases, respect cascade budgets, and record runs — with the 15-minute systemd timer demoted to heartbeat/backstop (its current cadence entrypoint becomes one trigger among several). Delta-driven waking is what makes agents an ecology rather than a cron job (G1, G2; honors T1's "no backstop" by keeping event-driven primary).
R4 — Route production writes through real mediation code change
Stop inserting pre-accepted proposals. Port the proof-harness WriteGate checks (evidence refs, confidence, permissions, ACL visibility, allowed op/edge types) into storage-harness as the single commit path; proposals enter pending and a mediation step decides. Mechanical containment only — no DB-level semantic judging, per D15 (G4).
R5 — Neutralize the substrate surface code change
Remove consumer must be reporter and the projection-name whitelist from Primeradiant.Soup; treat consumer/projection as opaque filter/scoping strings over substrate-owned material, and compute blockers only from substrate-owned health (completing T1514's direction) (G8).
R6 — Restore live inference to the recurring path, with a hardened model client code change
Make cadence synthesis call the live route by default (deterministic completion demoted to explicit fallback with honest producer_kind); replace the curl shell-out with a supervised HTTP client with timeouts, bounded retry/backoff, and typed transport-refusal records instead of raises; config-driven per-role model routes with the T1420 fallback chain (G3, G10, G14).
R7 — Grow the agent roster one species at a time through the same seam code changearchitecture change
Next species by product value: a connection/linking agent (edges beyond supports/duplicates), a contradiction scout (populating conflicts/contradicts), and a staleness keeper (state transitions instead of timestamp-only freshness). Each is a bounded, delta-driven worker writing proposals through R4's gate — proving B5's claim that new species need no changes to existing ones (G11).
R8 — Unify soup semantics into one library code change
Extract classification/op-building/mediation into a single module set used by both harnesses; quarantine the fixture-phrase Normalizer to fixture-only code paths as D11 already requires; make the golden corpus run through the production path per D10 (G9).
R9 — Minimum ecology observability observability change
Add Logger + :telemetry events for admission, agent run start/stop/refusal, commit, quarantine, cadence pass, and source freshness; persist audit events instead of holding them in memory; emit the already-computed packet/prompt/output hashes. Target: the three failure classes in B14 are distinguishable from substrate queries alone (G12, G7).
R10 — Decide the system-of-record question explicitly architecture changeticket/process change
Either promote SQLite to spec truth (port the Postgres enforcement triggers to SQLite constraints/app-level gates and amend D13), or schedule the Postgres migration the specs assume. The current state — invariants enforced only in an unused test database — is the worst of both (G5).
R11 — Reconcile the spec family with deployed truth ticket/process change
Add a short "deployed reality" addendum (or per-doc status banners) recording which D2/D5/D13 commitments are active, superseded, or deferred — the same pattern as D7's correction memo — so future implementation/review agents stop re-deriving the delta (G13).
