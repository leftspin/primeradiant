Contracts before code

primeradiant Elixir contracts

The handoff surface between product truth and implementation: Ecto invariants, context APIs, agent output schemas, and MCP tools for the Elixir/Phoenix build.

1. Contract doctrine

Rule: agents may be creative in proposals, never in committed truth. Every committed change passes through Ecto changesets, typed operations, evidence refs, and arbitration.

Committed graph is boring

Nodes, edges, story state, seen-state, and audit records are ordinary Ecto schemas over Postgres.

Agent output is hostile until validated

LLM JSON is not trusted. Validate shape, evidence, actor permissions, and graph operation semantics.

Authoring is accountable

Every user-facing sentence must trace to evidence packet refs and update seen-state precisely.

2. Ecto schema invariants

RawSource

External evidence envelope

required: tenant_id, source_type, external_id, observed_at, checksum, object_uri, acl
unique: tenant_id + source_type + external_id
invariant: raw source never decides story membership
Input

Canonical immutable item

required: raw_source_id, source_type, body_text or artifact_ref, observed_at
immutable after canonicalization except attrs extraction cache
invariant: one input can support many claims/stories; it is not itself the story
SoupNode

Story/claim/entity/watch/output graph node

required: tenant_id, node_type, title or summary, state, attrs
allowed node_type v1: input, story, claim, entity, user_watch, authored_output
invariant: story nodes represent situations that can change over time
SoupEdge

Named relationship

required: from_node_id, to_node_id, edge_type, confidence, status, evidence_refs
allowed status: proposed, weak, committed, rejected, superseded, retracted
invariant: no generic related edge
Proposal

Agent-submitted possible change

required: agent_run_id, proposed_ops, evidence_refs, confidence, status, rationale
allowed status: pending, accepted, accepted_weak, rejected, needs_more_evidence
invariant: proposals are inspectable and reversible before commit
UserSeenState

New-to-you boundary

required: user_id, story_id, seen_story_version, seen refs, last_briefed_at
invariant: global freshness is not user freshness

3. Graph operation contract

Agents submit operations, not prose instructions. The Arbiter decides whether those operations commit.

{
  "ops": [
    {
      "op": "create_node",
      "temp_id": "story:new:asteroid",
      "node_type": "story",
      "title": "New interstellar asteroid detected",
      "summary": "A situation that can receive future updates...",
      "attrs": { "scope": "public_news", "why_story_not_topic": "future observations can change it" },
      "evidence_refs": [{ "type": "input", "id": "inp_123", "span": [120, 240] }],
      "confidence": 0.82
    },
    {
      "op": "create_edge",
      "from": "inp_123",
      "to": "story:new:asteroid",
      "edge_type": "updates",
      "rationale": "The input reports a newly observed object relevant to this story.",
      "evidence_refs": [{ "type": "input", "id": "inp_123" }],
      "confidence": 0.78
    }
  ]
}

Allowed ops v1

  • create_node
  • create_edge
  • update_node_state
  • weaken_edge
  • supersede_edge
  • attach_evidence

Forbidden ops v1

  • delete_story
  • merge_story_destructive
  • rewrite_seen_state
  • commit_without_evidence
  • generic_related_edge

5. MCP tool surface

Agents use these tools before web search when the question concerns current story state, private context, user watches, or what is new to the user.

soup.search

Find nodes/inputs/stories/claims/entities/watches by semantic + filtered search.

soup.expand

Traverse the local graph with depth, edge type, confidence, and time bounds.

story.state

Return current projected story state and relevant evidence.

story.delta

Return changes since timestamp, version, authored output, or user seen-state.

soup.provenance

Trace a node/edge/claim/sentence to evidence, proposals, agent runs, and commits.

soup.propose

Submit graph operations as proposals with evidence and confidence.

watch.create

Create user story seeds, including /preferences/priorities and /stories/concepts anchors.

author.evidencePacket

Build bounded context for user-facing narration.

6. Validation gates

  1. Shape gate: LLM output must parse as declared JSON Schema.
  2. Changeset gate: every proposed node/edge/state change must pass Ecto changesets.
  3. Evidence gate: every proposed op cites source refs accessible to the actor.
  4. Relationship gate: edge type must be one of the named edge contracts and semantically valid for the node types.
  5. ACL gate: private evidence cannot leak into public story state or cross-user authoring.
  6. Arbitration gate: proposal status changes are audited and reversible.
  7. Seen-state gate: user seen-state updates only after verified authored output.

7. Test contract starter set

  • Agent proposal with no evidence is rejected before arbitration.
  • Agent proposal with generic related edge fails validation.
  • Story bigger-than/substory behavior creates new story + part_of edges, not destructive merge.
  • Duplicate input updates support/confidence/source weight without creating a fake material delta.
  • Stale story with user watch remains personally relevant even when global gravity is low.
  • User A private thread never appears in User B evidence packet.
  • Author output cannot record seen-state for claims it did not actually show.

This is the contract layer a senior engineer can turn into migrations, schemas, changesets, context tests, MCP tool specs, and Oban workers.
