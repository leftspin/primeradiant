Phoenix module map

primeradiant application shape

A concrete Elixir/Phoenix module and ownership map for implementation agents. This stops before code, but removes ambiguity about where product rules should live.

1. Rule of placement

Contexts own product truth. Controllers, LiveViews, MCP tools, Oban workers, and agents call contexts. They do not smuggle graph mutations or authoring rules around them.

Schemas validate shape

Ecto schemas and changesets reject invalid node/edge/proposal state.

Contexts validate meaning

Contexts enforce story-state invariants, proposal lifecycle, ACLs, and seen-state semantics.

Workers orchestrate only

Oban workers run jobs and call contexts; they should not contain product logic.

2. Top-level module tree

lib/primeradiant/
├── application.ex
├── repo.ex
├── accounts/                  # users/tenants/actors if needed
├── ingestion/                 # source adapters and canonical inputs
├── soup/                      # graph nodes, edges, story state, provenance
├── proposals/                 # agent proposals and typed graph operations
├── agents/                    # prompt registry, model calls, agent runs
├── arbitration/               # proposal decisions and commits
├── projections/               # derived story state, gravity, freshness, deltas
├── user_context/              # watches, priorities, seen-state
├── authoring/                 # evidence packets and authored outputs
├── mcp/                       # MCP tool adapter layer
└── observability/             # traces, costs, eval records

3. Context ownership

Primeradiant.Ingestion

Input truth

Owns RawSource, Input, Artifact, SourceSpan. It normalizes outside-world items but must not decide final story meaning.

Committed graph truth

Owns SoupNode, SoupEdge, StoryStateSnapshot, GraphCommit, provenance. It is the only context that exposes committed graph reads.

Owns Proposal, ProposedOp, EvidenceRef. It validates operation shape but does not decide product acceptance.

Commit authority

Owns proposal decisions and graph commits. It is the controlled seam between agent creativity and trusted soup state.

Primeradiant.UserContext

User-relative truth

Owns watches, `/preferences/priorities`, `/stories/concepts`, and seen-state. It prevents global rank from burying personal importance.

Owns evidence packets, authored outputs, verification state, and seen-state handoff. It writes only from bounded evidence.

5. Oban worker lanes

Ingestion workers

Fetch/import/canonicalize source items. Calls Ingestion.

Extraction workers

Run Claim & Entity Extractor. Calls Agents then Proposals.

Swarm workers

Run Story Seeker, Connection Weaver, Development Detector, Staleness Keeper, and other proposal agents.

Arbitration workers

Evaluate proposals and call Arbitration. Human review can be a branch, not a separate truth path.

Projection workers

Rebuild story state, gravity, freshness, unresolved counts, and user deltas from committed graph.

Authoring workers

Create evidence packets, draft/verify output, record authored output, and trigger seen-state updates.

7. Boundaries that should stay hard

  • Hard: agents cannot call Soup commit functions directly.
  • Hard: seen-state is updated only from verified authored outputs.
  • Hard: graph analytics are projections, not source of truth.
  • Hard: private ACL checks happen before prompt construction and before authoring.
  • Hard: no destructive story merge/split in v1; create better story nodes and named edges.
